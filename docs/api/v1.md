# The versioned JSON API (`/api/v1`)

Everything under `/api/v1` is JSON, and nothing under it names a particular
agent. The API talks to whatever agent is registered, and it answers in the
words written down here. A client written against this document works the
same whether the work is being done by a server backend or by a CLI on the
same machine, and it keeps working when a second backend shows up.

The document is the contract, and a gate checks it against the code in both
directions: an endpoint that exists but is not written down fails the build,
and so does an endpoint that is written down but no longer exists.

## Where the shapes live

The shapes are written down once, in `shared/src/api/v1.ts`, as schemas that
the backend validates every response against before it leaves. The same
shapes are published as JSON Schema in
[`docs/api/v1.schema.json`](./v1.schema.json), so a client that is not
written in TypeScript can generate its models from the same source of truth.
Regenerate that file with:

```bash
bun scripts/generate-v1-schema.ts
```

## Authentication

The versioned API sits behind the same session cookie as the rest of the
authenticated API. A client signs in through `/api/auth` and keeps the
cookie; every request below is made with it.

The gate that answers is the server's own gate - one session, or no
session - but it answers in the shape below, so a client that reads
`error.code` finds an object even on the very first request it makes.

## Query parameters

| Parameter | Meaning |
| --- | --- |
| `agent` | Which registered agent answers. Omit it and the default agent answers. |
| `directory` | The working directory the agent works in. |
| `limit` | How many sessions to return at most. Only on `GET /api/v1/sessions`. |
| `cursor` | Where to carry on from, as the agent handed it back. Only on `GET /api/v1/sessions`. |
| `search` | A word to look for among the sessions. Only on `GET /api/v1/sessions`. |

## Endpoints

| Method | Path | What it does | Shape |
| --- | --- | --- | --- |
| `GET` | `/api/v1` | What this API is and which agent answers by default | `ApiDescriptor` |
| `GET` | `/api/v1/agents` | The agents this server can talk to | `AgentListResponse` |
| `GET` | `/api/v1/sessions` | The sessions of one agent | `SessionListResponse` |
| `POST` | `/api/v1/sessions` | Start a session | `SessionResponse` |
| `GET` | `/api/v1/sessions/:id` | One session | `SessionResponse` |
| `PATCH` | `/api/v1/sessions/:id` | Rename a session | `SessionResponse` |
| `DELETE` | `/api/v1/sessions/:id` | Delete a session | `DeletedResponse` |
| `GET` | `/api/v1/sessions/:id/messages` | The messages of a session | `MessageListResponse` |
| `POST` | `/api/v1/sessions/:id/prompts` | Send a prompt to a session | `AcceptedResponse` |
| `POST` | `/api/v1/sessions/:id/abort` | Stop what a session is doing | `AcceptedResponse` |
| `GET` | `/api/v1/pending` | What the agent is waiting for | `PendingListResponse` |

### `POST /api/v1/sessions`

```json
{ "title": "Fix the failing test", "directory": "/path/to/work" }
```

Both fields are optional. `directory` falls back to the `directory` query
parameter.

### `PATCH /api/v1/sessions/:id`

```json
{ "title": "A better name" }
```

### `POST /api/v1/sessions/:id/prompts`

```json
{
  "parts": [
    { "type": "text", "text": "What the agent should do" },
    { "type": "file", "filename": "notes.txt", "mime": "text/plain", "url": "file:///path/to/notes.txt" }
  ],
  "model": { "providerId": "anthropic", "modelId": "claude-sonnet-4" },
  "agent": null,
  "variant": null
}
```

The prompt is accepted and the agent works on it in the background. Watch
`/api/v1/sessions/:id/messages` for what comes back.

A prompt that says nothing is not a prompt: the request has to carry words or a
file to hand over, so a caller who meant to say something cannot end up with an
empty turn in the conversation and no idea why.

`model`, `agent` and `variant` are all there even when they are null. A prompt
that does not care about them says so by saying null, and the agent picks the
one it would have picked anyway.

## The shapes

### `ApiDescriptor`

| Field | Type | Meaning |
| --- | --- | --- |
| `api` | `"v1"` | The version of this API |
| `name` | string | The name of the server |
| `version` | string | The version of the server |
| `defaultAgent` | string \| null | The agent that answers when nobody says |

### `Agent`

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | string | How a client asks for this agent |
| `label` | string | What to call it in a list |
| `kind` | `"server"` \| `"cli"` | Whether it is a service or a program on this machine |
| `capabilities` | string[] | What it can do: `sessions`, `messages`, `prompts`, `abort`, `events`, `permissions` |
| `status` | `"ready"` \| `"degraded"` \| `"unavailable"` | Whether it can answer right now |

**Which agents there are depends on the machine.** A program that is not
installed is listed as `unavailable` rather than left out, so that a client
can say "this one is not here" instead of "this one does not exist".

`unavailable` also covers an agent that is installed but cannot work yet -
not signed in, no provider, no API server key. The `detail` says which.

### `Session`

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | string | The id of the session |
| `agentId` | string | The agent the session belongs to |
| `title` | string | Its title. Empty when the agent has not given it one |
| `directory` | string \| null | Where it works. A session the agent does not place is given the directory it was asked about |
| `workspaceId` | string \| null | The working area it belongs to, when the agent has such a thing. Not the same as the directory: two checkouts of one repository are two directories and one workspace |
| `parentId` | string \| null | The session it forked from |
| `createdAt` | number | Milliseconds since the epoch. `0` when the agent does not say |
| `updatedAt` | number | Milliseconds since the epoch. `0` when the agent does not say |
| `archived` | boolean | Whether it is archived |
| `status` | `"idle"` \| `"busy"` \| `"unknown"` | What it is doing |
| `revert` | `SessionRevert` \| null | Where the conversation was rolled back to, when it was rolled back |
| `share` | `SessionShare` \| null | The link somebody else can read the conversation through, when it has one |

### `SessionRevert`

| Field | Type | Meaning |
| --- | --- | --- |
| `messageId` | string | The message the conversation was rolled back to |
| `partId` | string \| null | The part of it, when the rollback stopped inside a message |

### `SessionShare`

| Field | Type | Meaning |
| --- | --- | --- |
| `url` | string | Where somebody else can read the conversation |

### `SessionListResponse`

| Field | Type | Meaning |
| --- | --- | --- |
| `sessions` | `Session[]` | The sessions of this page |
| `nextCursor` | string \| null | Where the next page starts. `null` when this page is the last one |

The cursor is the agent's own, so a client hands it straight back. An agent
that has no notion of paging answers with every session it has and
`nextCursor: null`, which is the same thing as saying there is nothing more.

The key is always present even when its value is not. A client that has to ask
whether the field exists is a client that will eventually forget to ask, and
then it will loop over the last page forever.

### `Message`

A message is what was said. The pieces it is made of are asked for separately
and travel in their own place, because they arrive one at a time while the
conversation is happening.

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | string | The id of the message |
| `sessionId` | string | The session it belongs to |
| `role` | `"user"` \| `"assistant"` \| `"system"` | Who said it |
| `createdAt` | number | Milliseconds since the epoch. `0` when the agent does not say |
| `completedAt` | number \| null | When it was finished, if it was. `null` while it is still being answered |
| `cost` | number \| null | What it cost, if the agent counts |
| `tokens` | `TokenUsage` \| null | What it used, if the agent counts |
| `modelId` | string \| null | The model that answered |
| `providerId` | string \| null | Which provider that model came from |
| `agent` | string \| null | Which agent answered |
| `variant` | string \| null | Which variant of that agent answered |
| `parentId` | string \| null | The message it is a reply to |
| `error` | `MessageError` \| null | Why it went wrong, when it went wrong |

### `MessageWithParts`

| Field | Type | Meaning |
| --- | --- | --- |
| `info` | `Message` | What was said |
| `parts` | `MessagePart[]` | What it says, piece by piece |

`GET /api/v1/sessions/:id/messages` answers with `MessageListResponse`, whose
`messages` are `MessageWithParts`.

### `MessagePart`

A conversation is not only words. It is the thinking behind the words, the
tools that were called, the files that were read, the changes that were
proposed, the work that was handed to somebody else. The `type` says which kind
a part is, and each kind carries only the fields that kind has.

| `type` | Fields beyond `id` and `type` |
| --- | --- |
| `text` | `text`, `synthetic`, `time` |
| `reasoning` | `text`, `time` |
| `tool` | `callId`, `name`, `state` |
| `file` | `filename`, `mime`, `url` |
| `patch` | `hash`, `files` |
| `agent` | `name` |
| `subtask` | `agent`, `description`, `prompt`, `command` |
| `step-start` | `snapshot` |
| `step-finish` | `reason`, `snapshot`, `cost`, `tokens` |
| `snapshot` | `snapshot` |
| `retry` | `attempt`, `error`, `time` |
| `compaction` | `auto` |
| `other` | `text` |

`other` is what a part of a kind this API does not know becomes. It is not
dropped - a client that loses a piece of a conversation has lost part of the
answer - and it is not turned into text, so nothing draws it as the message's
words.

A `time` is `{ "start": number, "end": number | null }`: when it began, and
when it stopped if it has.

### `ToolCall`

| Field | Type | Meaning |
| --- | --- | --- |
| `callId` | string | The id of the call |
| `name` | string | The name of the tool |
| `state` | object | Where the call got to |

The `state` of a tool call has:

| Field | Type | Meaning |
| --- | --- | --- |
| `status` | `"pending"` \| `"running"` \| `"completed"` \| `"error"` | Where the call got to |
| `title` | string \| null | What the tool was doing, when the agent says |
| `output` | string \| null | What the tool said when it was done |
| `error` | string \| null | What went wrong, when something did |
| `input` | object \| null | What the tool was called with |
| `metadata` | object \| null | Whatever the agent attached to the call |
| `raw` | string \| null | The call as it was written down, before it was made sense of |
| `time` | `TimeRange` \| null | When it began, and when it stopped |

### `MessageError`

Why a message went wrong, in the words of this API rather than the words of
the agent that failed.

| Field | Type | Meaning |
| --- | --- | --- |
| `kind` | `"authentication"` \| `"output-length"` \| `"aborted"` \| `"api"` \| `"unknown"` | What kind of failure it is |
| `message` | string | What went wrong |
| `providerId` | string \| null | Which provider refused, when the failure is about credentials |
| `statusCode` | number \| null | The status the upstream answered with, when it answered with one |
| `isRetryable` | boolean \| null | Whether trying again could work |

An error nobody recognises is not an error nobody has: it is an unknown one,
and saying so is better than dropping the reason it failed.

### `TokenUsage`

| Field | Type |
| --- | --- |
| `input` | number |
| `output` | number |
| `reasoning` | number |
| `cacheRead` | number |
| `cacheWrite` | number |

### `PendingListResponse`

| Field | Type | Meaning |
| --- | --- | --- |
| `permissions` | `PendingPermission[]` | The permissions the agent is waiting for |
| `questions` | `PendingQuestion[]` | The questions the agent is waiting for |

Both kinds in one answer, because a caller that has to ask twice has to ask
twice for every working directory it watches.

### `PendingPermission`

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | string | The id of the request |
| `sessionId` | string | The session it belongs to |
| `directory` | string \| null | Where it works. `null` when the agent does not say |
| `permission` | string | What is being asked permission for |
| `patterns` | string[] | What the permission would allow, as the agent describes it |
| `metadata` | object | Whatever the agent attached to the request |
| `always` | string[] | The permissions that would always be allowed after this one |
| `tool` | `PendingRequestTool` \| null | The tool call it is about, when it is about one |

### `PendingQuestion`

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | string | The id of the request |
| `sessionId` | string | The session it belongs to |
| `directory` | string \| null | Where it works. `null` when the agent does not say |
| `questions` | `PendingQuestionInfo[]` | The questions being asked |
| `tool` | `PendingRequestTool` \| null | The tool call it is about, when it is about one |

### `PendingQuestionInfo`

| Field | Type | Meaning |
| --- | --- | --- |
| `question` | string | The question |
| `header` | string | A very short label for it |
| `options` | `PendingQuestionOption[]` | What can be answered |
| `multiple` | boolean | Whether more than one option may be chosen |

### `PendingQuestionOption`

| Field | Type | Meaning |
| --- | --- | --- |
| `label` | string | What the answer says |
| `description` | string \| null | What that answer means |

### `PendingRequestTool`

| Field | Type | Meaning |
| --- | --- | --- |
| `messageId` | string | The message the tool call is in |
| `callId` | string | The call itself |

A request belongs to a conversation, so the conversation decides whose it is.
An agent that cannot be waited on - a program that runs in a terminal, where
nobody is sitting in front of it - says so instead of answering with an empty
list that would mean "nothing is waiting".

## The event dialect

A conversation that is happening is not something a client polls for. The
events that describe it travel on the agent's event stream, and this API has
one dialect for them as well - the same dialect the answers are in, so that a
client never holds two shapes of the same conversation at once.

| `type` | What it says |
| --- | --- |
| `session.created` | A session came into existence |
| `session.updated` | A session changed |
| `session.deleted` | A session is gone |
| `session.idle` | A session stopped working |
| `session.compacted` | A session was compacted |
| `session.error` | A session failed |
| `message.updated` | A message changed |
| `message.part.updated` | A piece of a message changed |
| `message.part.delta` | More of a piece arrived |
| `message.part.removed` | A piece of a message was taken away |
| `message.removed` | A message was taken away |

The properties of each event are the shapes above: a session event carries a
`Session`, a message event carries a `Message`, and a part event carries a
`MessagePart`.

## When something goes wrong

Every failure answers with the same envelope, whatever went wrong - the
gate included:

```json
{ "error": { "code": "not_found", "message": "No session is known under that id" } }
```

`details` is there when there is something to say about it, such as the
issues of a request body that did not match the contract.

| Code | Status | Meaning |
| --- | --- | --- |
| `bad_request` | 400 | The request body did not match the contract |
| `unauthorized` | 401 | No session |
| `forbidden` | 403 | Not this session's |
| `not_found` | 404 | No such session |
| `agent_not_found` | 404 | No agent is registered under that id |
| `agent_unavailable` | 503 | That agent cannot answer right now |
| `upstream_error` | 502 | The agent answered with something unusable |
| `internal_error` | 500 | Something went wrong on this side |

## Versioning

The version is in the path. A shape that has to change in a way a client
would notice gets a new version, and the old one keeps answering for as long
as it is kept. Fields that are added do not need a new version: a client
that reads the fields it knows is unaffected by one it does not.
