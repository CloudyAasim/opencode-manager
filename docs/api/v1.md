# The versioned JSON API (`/api/v1`)

Everything under `/api/v1` is JSON, and nothing under it names a particular
agent. The API talks to whatever agent is registered, and it answers in the
words written down here. A client written against this document works the
same whether the work is being done by a server backend or by a CLI on the
same machine, and it keeps working when a second backend shows up.

The document is the contract, and a gate checks it against the code in both
directions: an endpoint that exists but is not written down fails the build,
and so does an endpoint that is written down but no longer exists.

## Where the shapes live

The shapes are written down once, in `shared/src/api/v1.ts`, as schemas that
the backend validates every response against before it leaves. The same
shapes are published as JSON Schema in
[`docs/api/v1.schema.json`](./v1.schema.json), so a client that is not
written in TypeScript can generate its models from the same source of truth.
Regenerate that file with:

```bash
bun scripts/generate-v1-schema.ts
```

## Authentication

The versioned API sits behind the same session cookie as the rest of the
authenticated API. A client signs in through `/api/auth` and keeps the
cookie; every request below is made with it.

The gate that answers is the server's own gate - one session, or no
session - but it answers in the shape below, so a client that reads
`error.code` finds an object even on the very first request it makes.

## Query parameters

| Parameter | Meaning |
| --- | --- |
| `agent` | Which registered agent answers. Omit it and the default agent answers. |
| `directory` | The working directory the agent works in. |

## Endpoints

| Method | Path | What it does | Shape |
| --- | --- | --- | --- |
| `GET` | `/api/v1` | What this API is and which agent answers by default | `ApiDescriptor` |
| `GET` | `/api/v1/agents` | The agents this server can talk to | `AgentListResponse` |
| `GET` | `/api/v1/sessions` | The sessions of one agent | `SessionListResponse` |
| `POST` | `/api/v1/sessions` | Start a session | `SessionResponse` |
| `GET` | `/api/v1/sessions/:id` | One session | `SessionResponse` |
| `PATCH` | `/api/v1/sessions/:id` | Rename a session | `SessionResponse` |
| `DELETE` | `/api/v1/sessions/:id` | Delete a session | `DeletedResponse` |
| `GET` | `/api/v1/sessions/:id/messages` | The messages of a session | `MessageListResponse` |
| `POST` | `/api/v1/sessions/:id/prompts` | Send a prompt to a session | `AcceptedResponse` |
| `POST` | `/api/v1/sessions/:id/abort` | Stop what a session is doing | `AcceptedResponse` |

### `POST /api/v1/sessions`

```json
{ "title": "Fix the failing test", "directory": "/path/to/work" }
```

Both fields are optional. `directory` falls back to the `directory` query
parameter.

### `PATCH /api/v1/sessions/:id`

```json
{ "title": "A better name" }
```

### `POST /api/v1/sessions/:id/prompts`

```json
{ "text": "What the agent should do" }
```

The prompt is accepted and the agent works on it in the background. Watch
`/api/v1/sessions/:id/messages` for what comes back.

## The shapes

### `ApiDescriptor`

| Field | Type | Meaning |
| --- | --- | --- |
| `api` | `"v1"` | The version of this API |
| `name` | string | The name of the server |
| `version` | string | The version of the server |
| `defaultAgent` | string \| null | The agent that answers when nobody says |

### `Agent`

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | string | How a client asks for this agent |
| `label` | string | What to call it in a list |
| `kind` | `"server"` \| `"cli"` | Whether it is a service or a program on this machine |
| `capabilities` | string[] | What it can do: `sessions`, `messages`, `prompts`, `abort`, `events` |
| `status` | `"ready"` \| `"degraded"` \| `"unavailable"` | Whether it can answer right now |

**Which agents there are depends on the machine.** A program that is not
installed is listed as `unavailable` rather than left out, so that a client
can say "this one is not here" instead of "this one does not exist".

### `Session`

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | string | The id of the session |
| `agentId` | string | The agent the session belongs to |
| `title` | string | Its title. Empty when the agent has not given it one |
| `directory` | string \| null | Where it works |
| `parentId` | string \| null | The session it forked from |
| `createdAt` | number | Milliseconds since the epoch. `0` when the agent does not say |
| `updatedAt` | number | Milliseconds since the epoch. `0` when the agent does not say |
| `archived` | boolean | Whether it is archived |
| `status` | `"idle"` \| `"busy"` \| `"unknown"` | What it is doing |

### `Message`

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | string | The id of the message |
| `sessionId` | string | The session it belongs to |
| `role` | `"user"` \| `"assistant"` \| `"system"` | Who said it |
| `createdAt` | number | Milliseconds since the epoch. `0` when the agent does not say |
| `completedAt` | number \| null | When it was finished, if it was |
| `parts` | `MessagePart[]` | What it says |
| `cost` | number \| null | What it cost, if the agent counts |
| `tokens` | `TokenUsage` \| null | What it used, if the agent counts |

### `MessagePart`

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | string | The id of the part |
| `type` | `"text"` \| `"reasoning"` \| `"tool"` \| `"file"` \| `"other"` | What kind of part it is |
| `text` | string \| null | The words, when the part has any |
| `tool` | `ToolCall` \| null | The tool, when the part is one |

### `ToolCall`

| Field | Type | Meaning |
| --- | --- | --- |
| `name` | string | The name of the tool |
| `state` | `"pending"` \| `"running"` \| `"completed"` \| `"error"` | Where the call got to |
| `title` | string \| null | What the tool was doing, when the agent says |
| `output` | string \| null | What the tool said when it was done. A call without its result says only that something was attempted |

### `TokenUsage`

| Field | Type |
| --- | --- |
| `input` | number |
| `output` | number |
| `reasoning` | number |
| `cacheRead` | number |
| `cacheWrite` | number |

## When something goes wrong

Every failure answers with the same envelope, whatever went wrong - the
gate included:

```json
{ "error": { "code": "not_found", "message": "No session is known under that id" } }
```

`details` is there when there is something to say about it, such as the
issues of a request body that did not match the contract.

| Code | Status | Meaning |
| --- | --- | --- |
| `bad_request` | 400 | The request body did not match the contract |
| `unauthorized` | 401 | No session |
| `forbidden` | 403 | Not this session's |
| `not_found` | 404 | No such session |
| `agent_not_found` | 404 | No agent is registered under that id |
| `agent_unavailable` | 503 | That agent cannot answer right now |
| `upstream_error` | 502 | The agent answered with something unusable |
| `internal_error` | 500 | Something went wrong on this side |

## Versioning

The version is in the path. A shape that has to change in a way a client
would notice gets a new version, and the old one keeps answering for as long
as it is kept. Fields that are added do not need a new version: a client
that reads the fields it knows is unaffected by one it does not.
